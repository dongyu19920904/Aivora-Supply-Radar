# AI 账号商机日报每日新鲜度实施方案

日期 2026-09-08，时区 Asia/Shanghai

## 一 保存近七期经营记忆

生成前从 Supply 仓库读取最近七期已发布日报。每期只保留标题、每日焦点、主商品、核验规格、进货参考、来源数量、老商家动作和异动标识。读取失败只降低去重能力，不能阻塞 AI 日报主体。

新的 replay 数据记录动态标题、焦点标识、新证据类型、主商品和当天异动标识。旧日报没有这些字段时，从可见 Markdown 恢复商品和动作，保证升级当天就能使用历史。

## 二 把六次货源核验分给不同平台

保留最多六次报价核验。先处理当天有真实变化且近七天未主推的商品，再覆盖 ChatGPT、Claude、Gemini、Grok、AI 编程和 AI 创作。相同分类不应提前用完全部名额。

核验门槛继续要求当前有货、价格大于零、规格明确、至少两个不同站点、原始链接有效和异常低价未命中。

## 三 增加商机新证据门槛

主推候选按下面顺序判断。

1. 首次达到新手门槛的商品。
2. 有尚未使用的补货或可核实降价信号。
3. 与上次同规格进货参考相比变化达到 2%。
4. 可复核站点数量或明确规格发生变化。
5. 近七天没有被主推的其他合格商品。

同一商品近七天出现过且以上条件都不满足时，不再主推。没有候选时生成观察版，不降低真实性门槛。

## 四 让标题和正文说明今天新在哪里

页面标题从当天事实生成。标题可以说明首次达到门槛、补货、可复核降价、断货、异常低价或没有新机会。标题末尾保留日期，便于归档和 SEO。

第一屏新增“今天新在哪里”。试卖版写出新商品或新变化，观察版明确写没有新证据。主按钮跟随当天任务，不能每天都指向同一个商品。

新手区保留最多六步，改为当天任务。固定的首次试卖全流程放到 `/guide/first-sale`，日报链接过去。商品说明仍只使用核验过的规格、交付和售后边界。

## 五 让老商家先看到新变化

已经在近七期出现的同一异动不再重复。长期缺货和长期异常价继续留在“今天暂停什么”，只有首次出现或状态恶化时才进入前三项。老商家前三项优先使用新断货、新异常价、明显涨价、明显降价和恢复供货。

没有新变化时显示一项当前经营的经营任务，例如核对待交付订单、补充备用来源或重算真实成本。文字必须明确这不是新市场需求。

## 六 收紧新闻关联

只读取当天主商品和当天异动商品。链接必须来自对应服务商的官方站点，并且正文涉及套餐、价格、地区、额度、登录、交付或售后。GitHub 开源项目、泛产品更新和社交转述不能进入日报。

## 七 加入发布校验

校验器读取近七期记忆并检查标题、焦点、主商品和异动。重复主推若没有价格、规格、来源或库存的新证据，发布失败。观察版必须明确没有新商机，不能伪装成试卖版。

继续保留库存、异常价格、来源数量、链接、首屏长度、步骤数量和禁用承诺校验。

## 八 前端配合

新增“首次低成本试卖”卖家指南，承接不会每天变化的完整流程。日报保留三种阅读方式、浏览器本地勾选、复制说明和利润计算器。

归档和详情页直接使用动态标题。手机宽度 390 像素时，动态标题、焦点说明和按钮不能溢出。

## 九 测试与发布顺序

1. 测试连续七天同一商品且没有变化时转为观察版。
2. 测试存在近期未用合格商品时自动换商品。
3. 测试达到 2% 的同规格降价允许再次推荐。
4. 测试同一异动不能连续使用。
5. 测试长期缺货不连续占据前三项。
6. 测试无关 GitHub 项目不能成为官方变化。
7. 测试动态标题和焦点写入发布内容。
8. 测试历史读取失败只降级，不阻塞主体日报。
9. 运行后端完整测试、Supply 根测试、V2 测试、类型检查、lint、内容校验和生产构建。
10. 对 2026-09-09 做 dry-run，并与 9 月 4 日到 8 日逐期比较。
11. 部署预览并检查桌面、390px 手机、日间和夜间。
12. 测试通过后 SSH 推送并沿用已有 GitHub Actions 和 Cloudflare 工作流发布。

生产日报不重复触发 2026-09-08。代码部署完成后由下一次正常定时任务使用新规则。
