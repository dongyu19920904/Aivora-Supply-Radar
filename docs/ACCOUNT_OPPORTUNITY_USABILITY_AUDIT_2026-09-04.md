# AI 账号商机日报可用性审计

日期：2026-09-04（Asia/Shanghai）
事实基线：`https://supply.aivora.cn/opportunities/latest`、Aivora-Supply-Radar `origin/main`、CloudFlare-AI-Insight-Daily `origin/main`

## 结论

当前日报已经能引用实时货源、隔离异常低价、提醒缺货和提供利润计算器，但它仍是一张“信息很多的经营清单”，还不是零基础卖家可以从第一个按钮开始完成一次低成本试卖的操作页。主要问题不是缺少内容，而是决策、步骤和证据混在一起，同一商品反复出现，老商家又看不到清楚的“最近 24 小时变化”。

本轮保持 `supply-merchant-daily-v3` 的确定性生成方式，不增加大模型调用。改造重点是让同一份真实货源快照分别服务三类用户：零基础用户先得到一个明确按钮，新手最多执行六步，老商家先处理最多三个变化或停单风险。

## 真实链路

```text
Supply V2 商品与报价数据库
  -> /api/opportunities/snapshot
  -> Worker 读取并校验快照
  -> 商品筛选与异常低价隔离
  -> 确定性 Markdown 生成
  -> 发布校验
  -> 提交 Supply 仓库 content/cn/account-opportunity
  -> 同步 Supabase account_opportunities
  -> Supply V2 /opportunities/[date]
  -> /opportunities/latest
```

账号商机生成失败由独立隔离层处理，不阻塞 AI 日报主体。定时工作流按 Asia/Shanghai 日期检查缺失内容后才触发，不应手工重复生产同一天日报。

## 分用户问题

### 一眼看懂用户

- 页面标题、描述和三个通用按钮先占据首屏，用户还要继续阅读才能找到当天唯一动作。
- “成本口径”“同规格来源”“保本价”等词没有就地解释。
- 当前首屏同时讲结论、数据、库存、风险和经营前提，认知负担过高。
- 页面没有“开始今天的任务”这一条清晰主路径。

### 第一次试卖的新手

- 当前推荐门槛只验证“有报价、价格大于零、非异常低价”，没有证明报价来自至少两个不同货源站。
- `availableOfferCount` 是报价行数，不等于独立货源站数量。线上 ChatGPT Plus 正价代充前 50 条当前可买报价来自 44 个不同渠道名称、16 个链接域名，但生成器没有读取这项证据。
- 步骤分散在商品说明、利润链接、门槛和停止条件里，完成一个步骤后没有进度反馈。
- 利润计算器会预填售价、销量和费用示例，容易让零基础用户误把演示值当成自己的真实经营数据。
- 没有安全的可复制商品说明草稿，也没有强制保留“付款前再次确认库存”。

### 已有订单的老商家

- 当前最多三个动作有风险提示，但“当前盘面”“关键异动”“暂停清单”重复介绍同一商品。
- 异动、拥挤和低供给混排；其中“拥挤”和“低供给”是当前状态，不是相对上一份快照的变化。
- 没有先说明今天是否存在可比较的连续历史快照。
- 动作排序没有严格按待停单风险、异常价格、断货、明显价格变化、核心平台依次处理。

## 内容和交互问题

1. 日报结构以栏目为中心，不以用户要完成的任务为中心。
2. 同一商品在新手、老商家、关键异动和页尾相关推荐中重复出现。
3. 第一屏没有控制在约 300 个中文字符内。
4. Markdown 本身可读，但前端没有三种阅读入口、勾选进度和复制说明。
5. 页面页尾再次列出最多三个“相关货源”，会增加重复和选择困难。
6. 手机端长链接由 Markdown prose 直接渲染，缺少专门的断行和操作按钮布局。
7. 历史日报需要保持兼容，不能只让新格式可读。

## 数据边界

- 货源快照能证明当前报价、库存状态、记录时间和连续抓取中的价格或库存变化。
- 报价数量不能证明销量、询问量、真实需求或盈利能力。
- Codex 不知道卖家的真实售价、手续费、退款损耗、售后成本和获客成本；这些字段必须由用户填写。
- 新闻只能说明官方套餐、地区、额度、政策或交付规则的变化，不能替代当天货源证据。
- 当无法证明至少两个不同货源站、规格不能对齐或售后边界不清时，日报必须发布“今日不建议上新”，而不是降低门槛。

## 目标状态

新日报的首屏只回答今天试卖、观察还是暂停，下一步点击哪里，以及最大的亏损风险。正文提供“一眼看懂、新手照做、老手看盘”三个入口；新手只得到一个达到门槛的商品和最多六步；老商家只得到最多三个优先动作。所有价格、库存和变化都保留到同一次快照或连续快照的可追溯关系。
