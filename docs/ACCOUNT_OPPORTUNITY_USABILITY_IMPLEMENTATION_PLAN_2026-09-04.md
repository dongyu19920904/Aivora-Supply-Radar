# AI 账号商机日报改造实施方案

日期：2026-09-04（Asia/Shanghai）

## 实施原则

- 保留 `supply-merchant-daily-v3`、异常低价隔离、库存校验、Asia/Shanghai 日期和账号商机失败隔离。
- 不增加大模型调用；多来源核验使用 Supply V2 现有公开商品报价接口，失败时降级为“不建议上新”。
- 不修改 AI 日报、AI 商机和 AI 趣闻的独立逻辑。
- 不编造售价、销量、市场需求和利润；真实经营字段由用户填写。
- Markdown 是完整事实底稿，关闭 JavaScript 仍能阅读；前端交互只负责切换、勾选和复制同一份内容。

## 阶段一：补齐推荐证据

1. Worker 读取货源快照后，只对优先候选商品发起有上限的报价核验。
2. 从当前可购买报价中计算不同渠道名称和不同链接域名，记录核验时间。
3. 新手商品必须同时满足有货、价格大于零、非异常低价、核心品类、至少两个不同可复核来源、有效商品页和计算器入口。
4. 任一核验请求失败时保留日报主体，但该商品不能进入新手推荐。
5. 报价行数继续显示为供给信息，不再把它写成“已经准备了两个来源”。

## 阶段二：重写确定性日报

按以下固定结构生成：

1. `今天一句话`：四条以内，给出建议、唯一按钮、最大风险和数据时间，总可见文字约 300 个中文字符以内。
2. `选择你的阅读方式`：三个锚点入口。
3. `一眼看懂`：最多一个商品、可复核进货价、来源数量、停止条件和普通中文解释。
4. `新手今天照着做`：最多六个单动作步骤；没有合格商品时改为暂停与记录步骤。
5. `老商家今天看这三项`：先展示最近 24 小时连续快照变化；没有可比较数据时明确说明；动作最多三个。
6. `今天暂停什么`：缺货和异常价格，避免在前文重复完整介绍。
7. `数据和判断依据`：同一快照统计、链接、时间、术语解释和直接相关的官方变化。
8. `收盘填写结果`：询问、成交、实际采购成本、退款/补发和售后耗时均留待卖家填写。

内部 replay 元数据增加当天建议、主商品、可复核进货价、来源数量、商品页、计算器和安全复制草稿，保持 v3 标识不变，供 Supply V2 展示使用。

## 阶段三：更新发布校验

- 校验新章节、首屏长度、禁用承诺和禁用虚构售价。
- 校验新手最多一个商品、最多六步、合格商品必须有至少两个可复核来源。
- 校验老商家最多三个动作，涨跌必须来自连续快照信号。
- 校验缺货和异常商品不能进入新手推荐。
- 校验统计数字和商品链接来自本次快照允许集合。
- 无合格商品时允许发布“今日不建议上新”，同时必须保留停单和复盘信息。

## 阶段四：改造 Supply V2 页面

- 服务端解析新格式章节和 replay 元数据，继续兼容旧日报。
- 首屏展示当天建议、主按钮、最大风险、更新时间和货源有效性。
- 增加“一眼看懂、新手照做、老手看盘”切换，默认一眼看懂。
- 新手步骤使用本地浏览器存储记录勾选进度，不写入服务器。
- 增加复制商品说明按钮，复制内容固定包含“付款前再次确认库存”。
- 移除会重复选择的页尾通用商品卡；正文只保留本日报引用的短链接。
- 利润计算器只自动带入货源成本，售价、数量和各项费用为空并显示“待填写”，输入完整前不输出利润判断。
- 使用 `noscript` 回退显示完整 Markdown；日间、夜间和约 390px 手机均可操作。

## 阶段五：测试与发布

后端新增或更新测试覆盖：

1. 正常有货且有合格新手商品。
2. 所有核心商品缺货。
3. 最低价异常但质保价格正常。
4. 只有一个可复核来源。
5. 没有可比较的连续历史快照。
6. 明显涨价、降价和断货。
7. 新闻与商品无关。
8. 账号商机失败不阻塞 AI 日报主体。

前端测试覆盖章节解析、三种阅读模式、新手步骤上限、复制提醒和利润计算缺少售价。发布前运行两个仓库已有的完整测试、类型检查、lint、内容检查与生产构建。随后执行指定日期 dry-run，部署预览，检查桌面与 390px 手机的日间/夜间模式。只有全部通过才提交、SSH 推送并沿用现有工作流部署；生产日报最多触发一次。

## 验收记录模板

- 首屏首个主按钮在十秒内可找到。
- 首屏无需理解行业术语，正文首屏说明不超过约 300 个中文字符。
- 新手推荐 0 或 1 个商品，步骤不超过六个。
- 老商家动作不超过三个。
- 售价、费用和真实结果均由用户填写。
- 每个价格可追溯到本次快照；每个涨跌可追溯到连续快照。
- 页面无利润保证、虚构需求、异常低价推荐或缺货推荐。
- JS 关闭可读，390px 无横向溢出，日夜主题可辨。
- 完整验证通过后记录提交 SHA、工作流、线上地址和回滚提交。
